Kairos Automata

Dashboard Strategies BackTester

Overview

Kairos Automata is an automated trade execution and logging system. TradingView sends trade signals as webhooks, the app logs them and forwards orders to Interactive Brokers for execution, and results are displayed on the dashboard.

Trade Flow

TradingView Alert
  │  POST /webhook?token=... with JSON payload
  ▼
Web Service (app.py)
  │  1. Validates webhook token
  │  2. Logs trade to PostgreSQL
  │  3. Routes to IB broker (when broker="ib")
  ▼
IB Broker (ib_broker.py)
  │  Connects to IB Gateway via internal network
  │  For stocks: places market or limit order directly
  │  For options: fetches chain, selects ATM contract within spread limit, places order
  ▼
IB Gateway Service
  │  Forwards order to Interactive Brokers servers
  ▼
Order Executed → Result logged → Visible on dashboard

Railway Services

ServiceDescription
web Runs the Flask/Gunicorn app. Handles incoming webhook signals from TradingView, maintains a PostgreSQL database of all trades, and serves the dashboard UI. Connects to IB Gateway via the internal Railway network.
ib-gateway Runs the IB Gateway application inside Docker. IBC (IB Controller) automates the login process. Exposes the IB API internally on port 4002, proxied to port 4004 via socat. Configured to trade in paper (simulation) mode.

Webhook Payload — Stocks

TradingView alerts POST the following JSON to trigger a stock trade:

{% raw %}{
  "ticker": "{{ticker}}",
  "action": "{{strategy.order.action}}",
  "sentiment": "{{strategy.market_position}}",
  "quantity": "100",
  "price": "{{close}}",
  "time": "{{timenow}}",
  "strategy": "STRATEGY_NAME",
  "interval": "{{interval}}",
  "broker": "ib"
}{% endraw %}

Webhook Payload — Options

Add "sec_type": "OPT" to route the signal to an options contract instead of the underlying stock. The app automatically selects the nearest Friday expiry and finds the closest ATM contract whose bid/ask spread is within the max_spread limit.

{% raw %}{
  "ticker": "{{ticker}}",
  "action": "{{strategy.order.action}}",
  "quantity": 1,
  "price": {{close}},
  "sec_type": "OPT",
  "max_spread": 1.00,
  "strike_offset": 0,
  "broker": "ib"
}{% endraw %}

Options Payload Fields

FieldDefaultDescription
sec_type "STK" Set to "OPT" to trade an options contract. Omit or use "STK" for the underlying stock.
price required Current price of the underlying (use {{close}}). Used to find the ATM strike.
max_spread 1.00 Maximum bid/ask spread in dollars. The app scans strikes outward from ATM and picks the first contract within this limit.
strike_offset 0 Number of strikes away from ATM. 0 = ATM, 1 = one strike OTM, 2 = two strikes OTM, etc.
option_expiry next Friday Override the expiry date as "YYYYMMDD". If omitted, uses the nearest weekly Friday expiry from the chain.

Options — How It Works

TradingView Alert (sec_type: OPT)
  │  BUY action → Call option
  │  SELL action → Put option
  ▼
app.py — options branch
  │  1. Routes request to background IB thread (event loop affinity)
  ▼
ib_broker.select_option()
  │  1. reqSecDefOptParams → fetch full option chain
  │  2. Find nearest Friday expiry from chain
  │  3. Sort strikes by distance from underlying price
  │  4. reqTickers → check bid/ask for each strike
  │  5. Return first contract with spread ≤ max_spread
  ▼
ib_broker.place_order(sec_type="OPT")
  │  Market order on selected contract
  ▼
Fill logged to dashboard
