Overview

Kairos Automata is an automated trade execution, logging, and analysis platform built by Bill Dorais. TradingView alerts are received as webhooks and routed through a configurable Signal Router pipeline before being forwarded to a supported broker — Alpaca, Interactive Brokers, or Coinbase — for execution. The dashboard separates Alpaca Fills and TV Signals into dedicated tabs, shows cumulative P&L with a multi-select strategy visibility picker (Top 10/15/20, eye-toggle per strategy), and syncs the equity chart to whichever feed tab is active.

Beyond live trading, the platform includes a full backtesting and optimisation suite. The Backtester runs a single strategy over Alpaca or Yahoo Finance data. The Optimizer sweeps parameter ranges across multiple tickers and timeframes using random search, exports the best result as a ready-to-use Pine Script, and compares Python vs TradingView results side-by-side. The Variants browser fans user-saved strategies out across tickers and timeframes, auto-populates defaults from the live strategy params, applies an IS/OOS walk-forward gate, and provisions approved variants directly into the Signal Router.

The Progress page tracks TradingView alert setup per ticker using the naming convention CAM_TICKER_STRAT_LEVEL_TFMIN (e.g. CAM_SPY_BREAKOUT_R4S4_05MIN). Alerts can be renamed, tickers deleted, and progress checked off as alerts go live.

Risk Management

Three independent safety guards run alongside the signal router. All limits are set from the Risk panel at the top of the Signal Router page and are saved to .env so they survive restarts. The panel refreshes every 15 seconds and shows today's P&L, open positions, and any blocked strategies.

GuardEnv VarHow it works
Daily Max Loss MAX_DAILY_LOSS A background thread polls account P&L every 60 seconds. When today's total (realized + unrealized) drops to or below this value, two things happen simultaneously: all open positions are liquidated across every active broker, and an account-wide halt is set that blocks every subsequent incoming order until manually cleared. The halt is cleared with the Clear Halt & Resume Trading button in the risk panel. Set to a negative dollar value to enable (e.g. -500). Default: disabled.
Per-Position Stop MAX_POSITION_LOSS A background thread polls all open positions every 5 seconds across all active brokers (Alpaca, IB paper, IB live). When any single position's unrealized P&L drops to or below this value, that position is closed immediately. The strategy stays active and is free to take a new entry on the next signal. Set to a negative dollar value to enable (e.g. -200). Default: disabled.
Trailing Stop MAX_TRAILING_GIVEBACK Backup trailing stop for cases where a TradingView exit alert fails to deliver. Tracks each open position's peak unrealized P&L since entry. Once the peak reaches the giveback amount, the stop is armed; if the position then gives back that same amount from peak, it is closed immediately. Only fires on profitable positions — losses are left to the per-position stop above. Strategy stays active. Set to a positive dollar value to enable (e.g. 30). Default: disabled.
Duplicate Signal Filter SIGNAL_COOLDOWN_SECS Drops a signal silently if the same strategy + ticker + action combination has already been received within the cooldown window. Prevents double-fills caused by TradingView alert retries or accidental duplicate alerts. The response includes the remaining cooldown time. Default: 10 seconds.

Signal Router — Pipeline Nodes

Each pipeline intercepts signals by strategy name and applies a chain of nodes before placing an order. Pipelines sort alphabetically and are colour-coded by prefix group (e.g. all CAM_SPY_BREAKOUT rules share one border colour). Duplicate via the ⧉ button.

NodeDescription
StrategyMatches the incoming strategy name. Supports wildcards, e.g. CAM_MSFT*. If omitted, the pipeline matches all signals.
InstrumentOverrides the instrument type: STK (stocks), OPT (options), FUT (futures), CRYPTO.
Options ConfigFor options signals — sets target premium (mid-price), expiry type (weekly/monthly), and side (auto/call/put).
QuantityOverrides the order size in shares, dollar amount, or % of account. Fractional quantities supported for crypto.
ModeRoutes to the IB paper account or IB live account. Does not affect Alpaca/Coinbase routing.
BrokerSelects the execution broker: IB, Alpaca, or Coinbase. Overrides the "broker" field in the TradingView payload.
Ticker OverrideForces a specific ticker regardless of what TradingView sends.
Trading HoursDrops signals arriving outside a configured session window (e.g. 09:30–16:00 ET). No trade is logged.

Dashboard — Trade Feed

The trade feed has two tabs: Alpaca Fills (default) shows clean Alpaca execution rows with paired P&L; TV Signals shows TradingView signals paired into entry/exit trades with computed P&L. Switching chart tabs (Alpaca P&L / Signals P&L) also switches the feed tab. The equity chart supports click-to-exclude individual trades on both tabs.

Webhook Payload — Stocks

TradingView alerts POST the following JSON. The strategy field must match the pipeline name exactly. Use {% raw %}{{strategy.order.alert_message}}{% endraw %} for the action field so LONG/SHORT/EXIT signals are passed through correctly.

{% raw %}{
  "ticker": "{{ticker}}",
  "action": "{{strategy.order.alert_message}}",
  "sentiment": "{{strategy.market_position}}",
  "quantity": 1,
  "price": {{close}},
  "time": "{{timenow}}",
  "strategy": "CAM_SPY_BREAKOUT_R4S4_05MIN",
  "interval": "{{interval}}"
}{% endraw %}

Webhook Payload — Options (pipeline-driven)

The recommended approach is to set the Instrument node to OPT and add an Options Config node in the Signal Router. The pipeline then selects the contract automatically — no options fields needed in the TradingView payload.

{% raw %}{
  "ticker": "{{ticker}}",
  "action": "{{strategy.order.action}}",
  "quantity": 1,
  "price": {{close}},
  "time": "{{timenow}}",
  "strategy": "CAM_PLTR_V6_5MIN"
}{% endraw %}

Options Config Node — How It Works

TradingView Alert → Signal Router matches pipeline
  │  Instrument node sets sec_type = OPT
  │  Options Config node sets target_premium = $1.00, expiry = weekly
  │  BUY action → Call option / SELL action → Put option (Auto mode)
  ▼
ib_broker.select_option_by_premium()
  │  1. reqSecDefOptParams → fetch full option chain (expirations + strikes)
  │  2. Resolve expiry — nearest Friday (weekly) or third Friday (monthly)
  │  3. Select ~25 strikes centred around the current underlying price
  │  4. reqTickers (bulk) → get live bid/ask for all candidates in one call
  │  5. Pick strike whose mid-price ((bid+ask)÷2) is closest to target_premium
  ▼
ib_broker.place_order(sec_type="OPT")
  │  Market order on selected contract
  ▼
Fill synced → logged to dashboard

Recent Updates

AreaWhat changed
Naming Convention All routing rules and TradingView alerts now follow CAM_TICKER_STRAT_LEVEL_TFMIN (e.g. CAM_SPY_BREAKOUT_R4S4_05MIN). The Progress page parses both old and new formats and auto-generates rules in the new convention when adding a ticker. Alert names and routing rules can be renamed or deleted per-ticker directly from the page.
Dashboard — Trade Feed Split The trade feed is now split into Alpaca Fills and TV Signals tabs to eliminate confusing paired rows. Switching chart tabs syncs the feed tab and vice versa. The equity chart supports a shared date filter (persisted across pages via localStorage) and click-to-exclude on both tabs. Strategy visibility buttons include Top 10 / 15 / 20 quick-selects ranked by realised P&L.
Signal Router Theming Pipelines are sorted alphabetically and colour-coded by name prefix — each ticker group shares a border hue (greens only, constrained to the palette), with BREAKOUT more saturated and REVERSAL more muted within the same group. Buttons use an outlined green style.
Variants — Live Defaults The Variants page now fetches parameter defaults directly from the saved strategies in the DB on every load, so the config is always in sync with the latest strategy params. Only user-saved strategies are shown (built-ins are hidden).
Analysis — Date Filter The leaderboard and all analysis stats now have a From/To date filter. Dates are shared with the dashboard via localStorage so setting a session start date on either page applies everywhere — useful for a clean start when moving from testing to live trading.
Strategy Rename User-saved strategies can be renamed inline on the /strategies page (slug stays the same to preserve references). Routing rules on the /progress page can be renamed via the pencil icon.
IB Disabled by Default IB broker is now off unless IB_ENABLED=true is set, preventing IB connection errors from affecting Alpaca-only deployments.
Webhook Action Field The recommended TradingView payload now uses {% raw %}{{strategy.order.alert_message}}{% endraw %} for the action field so LONG/SHORT/EXIT signals pass through correctly and count toward performance stats.
